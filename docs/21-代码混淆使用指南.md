# 代码混淆使用指南

## 📋 概述

本项目使用 `javascript-obfuscator` 对微信小程序代码进行高级混淆，提供比基础压缩更强的代码保护。

---

## 🎯 混淆级别对比

| 保护措施 | 基础构建 | 混淆构建 |
|---------|---------|---------|
| 变量名压缩 | ✅ `a,b,c` | ✅ `_0x1a2b` |
| 代码压缩 | ✅ 单行 | ✅ 单行 |
| 控制流混淆 | ❌ | ✅ 逻辑打乱 |
| 字符串加密 | ❌ | ✅ Base64 编码 |
| 死代码注入 | ❌ | ✅ 干扰分析 |
| 对象键转换 | ❌ | ✅ 混淆属性名 |
| 字符串数组 | ❌ | ✅ 提取到数组 |

**安全级别提升**: ⭐⭐⭐ → ⭐⭐⭐⭐

---

## 🚀 使用方法

### 本地构建

#### 方式 1：普通构建（基础保护）

```bash
pnpm run build:mp-weixin
```

适用于：
- ✅ 开发测试
- ✅ 快速构建
- ✅ 调试需要

#### 方式 2：安全构建（高级混淆）

```bash
pnpm run build:mp-weixin:secure
```

适用于：
- ✅ 生产环境
- ✅ 正式发布
- ✅ 需要更强保护的版本

### CI/CD 自动构建

GitHub Actions 已配置为默认使用安全构建：

```yaml
# .github/workflows/deploy-weixin.yml
- name: 构建微信小程序
  run: pnpm run build:mp-weixin:secure
```

推送代码到 `main` 分支后，会自动执行混淆构建。

## ⚙️ 混淆配置说明

### 当前配置 (`scripts/obfuscate.js`)

```javascript
{
  compact: true,                        // 代码压缩为一行
  controlFlowFlattening: true,         // 控制流扁平化 ⭐
  controlFlowFlatteningThreshold: 0.75, // 75% 代码应用

  identifierNamesGenerator: 'hexadecimal', // 十六进制命名 ⭐

  stringArray: true,                    // 字符串数组 ⭐
  stringArrayThreshold: 0.8,            // 80% 字符串
  stringArrayEncoding: ['base64'],      // Base64 编码 ⭐

  deadCodeInjection: true,              // 死代码注入 ⭐
  deadCodeInjectionThreshold: 0.4,      // 40% 代码块

  transformObjectKeys: true,            // 对象键转换 ⭐
}
```

**标注 ⭐ 的是核心混淆特性**

### 性能 vs 安全权衡

| 配置项 | 当前值 | 安全性 | 性能影响 | 体积影响 |
|--------|--------|--------|----------|----------|
| controlFlowFlatteningThreshold | 0.75 | 高 | 中 | +15% |
| stringArrayThreshold | 0.8 | 高 | 低 | +10% |
| deadCodeInjectionThreshold | 0.4 | 中 | 中 | +20% |

**总体影响**：
- 📦 包体积：+30-50%
- ⚡ 运行性能：-3-5%
- 🛡️ 安全性：提升 40-60%

## 🔧 自定义配置

### 调整混淆强度

编辑 `scripts/obfuscate.js`：

#### 降低混淆强度（更快构建，体积更小）

```javascript
{
  controlFlowFlatteningThreshold: 0.5,  // 75% → 50%
  stringArrayThreshold: 0.5,             // 80% → 50%
  deadCodeInjection: false,              // 关闭死代码注入
}
```

#### 提高混淆强度（更强保护）

```javascript
{
  controlFlowFlatteningThreshold: 1.0,   // 75% → 100%
  stringArrayThreshold: 1.0,              // 80% → 100%
  deadCodeInjectionThreshold: 0.6,        // 40% → 60%
  debugProtection: true,                  // 启用调试保护（影响性能）
  disableConsoleOutput: true,             // 禁用 console（生产环境）
}
```

### 排除特定文件

编辑 `scripts/obfuscate.js`：

```javascript
const excludePatterns = [
  '**/node_modules/**',
  '**/vendor.js',           // 第三方库
  '**/config.js',           // 配置文件
  '**/components/某组件.js', // 特定组件
];
```

## ⚠️ 注意事项

### 1. 构建时间

混淆会增加构建时间：
- 普通构建：~30 秒
- 混淆构建：~60-90 秒

### 2. 包体积增加

混淆后包体积会增加 30-50%：
- 原始：500KB → 混淆：650-750KB

**影响**：
- ✅ 仍在微信小程序 2MB 限制内
- ⚠️ 首次加载时间略有增加

### 3. 运行性能

混淆代码运行时性能略有下降：
- 性能损失：3-5%
- 用户感知：几乎无影响

### 4. 调试困难

混淆后的代码难以调试：
- ✅ 开发时使用：`pnpm run build:mp-weixin`
- ✅ 生产时使用：`pnpm run build:mp-weixin:secure`

### 5. Source Map

**重要**：不要生成 source map！

当前配置已禁用：
```javascript
sourceMap: false
```

如果开启 source map，混淆保护将失效。

## 🛠️ 故障排查

### 问题 1：混淆后代码报错

**症状**：混淆后小程序无法运行

**解决方案**：
1. 检查是否使用了动态代码执行（eval、Function）
2. 排除有问题的文件：
```javascript
const excludePatterns = [
  '**/有问题的文件.js',
];
```

### 问题 2：包体积过大

**症状**：混淆后超过 2MB 限制

**解决方案**：
1. 降低混淆强度
2. 排除大文件（如 vendor.js）
3. 启用分包加载

### 问题 3：构建时间过长

**症状**：构建超过 5 分钟

**解决方案**：
1. 降低混淆阈值
2. 排除不重要的文件
3. 使用更快的机器

## 📝 最佳实践

### ✅ 推荐做法

1. **开发环境**：使用普通构建，快速调试
2. **生产环境**：使用混淆构建，增强保护
3. **渐进式保护**：先测试普通混淆，再调整强度
4. **关键代码优先**：优先混淆支付、认证等敏感逻辑
5. **定期更新**：保持 javascript-obfuscator 最新版本

### ❌ 避免做法

1. ❌ 不要在开发时使用混淆（影响调试）
2. ❌ 不要过度混淆（影响性能）
3. ❌ 不要依赖客户端保护关键逻辑（用服务端验证）
4. ❌ 不要生成 source map（会暴露源码）
5. ❌ 不要在 Git 中提交混淆后的代码（用 CI 自动构建）
