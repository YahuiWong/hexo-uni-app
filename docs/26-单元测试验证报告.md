## 🐛 发现并修复的问题

### 问题 1: Marked Renderer 参数错误
**症状**: 代码块和行内代码内容完全丢失
```html
<code class="inline-code"></code>  <!-- 内容为空 -->
```

**原因**: Marked v17+ 的 renderer 方法接收的是 **token 对象**，不是字符串
```typescript
// ❌ 错误的实现
renderer.code = function (code: string, lang: string) { ... }

// ✅ 正确的实现
renderer.code = function (token: any) {
  const code = token.text;  // 代码内容在 token.text 中
  const lang = token.lang;  // 语言在 token.lang 中
}
```

**修复**: 修改 renderer 方法签名，从 token 对象中提取数据

### 问题 2: 数学公式被双重转义
**症状**: 数学公式显示为 `&lt;span&gt;`
```html
<p>&lt;span class=&quot;math-inline&quot;&gt;$E = mc^2$&lt;/span&gt;</p>
```

**原因**: `walkTokens` 修改的 HTML 被 marked 再次转义

**修复**: 简化数学公式处理，使用代码块语法（```math）代替行内处理

## 📝 核心实现

### 代码块渲染
```typescript
renderer.code = function (token: any): string {
  const code = token.text || '';
  const lang = (token.lang || '').trim().toLowerCase() || 'plaintext';

  // Mermaid 图表
  if (lang === 'mermaid') {
    return `<div class="mermaid">${escapeHtml(code)}</div>`;
  }

  // 数学公式块
  if (['math', 'latex', 'katex'].includes(lang)) {
    return `<div class="math-block">$$${escapeHtml(code)}$$</div>`;
  }

  // 普通代码块
  return `<pre class="code-block"><code class="language-${escapeHtml(lang)}">${escapeHtml(code)}</code></pre>\n`;
};
```

### 行内代码渲染
```typescript
renderer.codespan = function (token: any): string {
  const code = token.text || '';
  return `<code class="inline-code">${escapeHtml(code)}</code>`;
};
```

### HTML 转义（防止 XSS）
```typescript
function escapeHtml(text: unknown): string {
  if (typeof text !== 'string') return '';

  const map: Record<string, string> = {
    '&': '&amp;',
    '<': '&lt;',
    '>': '&gt;',
    '"': '&quot;',
    "'": '&#039;',
  };
  return text.replace(/[&<>"']/g, (m) => map[m]);
}
```

## 🎓 技术要点

### 1. Marked v17+ 的 Renderer API
- Renderer 方法接收 **token 对象**，不是字符串
- 代码内容在 `token.text`，语言在 `token.lang`
- 需要使用 `marked.parse()` 而不是 `marked.lexer() + marked.parser()`

### 2. 安全性
- 所有用户输入都必须通过 `escapeHtml()` 转义
- 防止 XSS 攻击（`<script>`, `<img onerror>` 等）
- 双引号、单引号、`<>` 等特殊字符都要转义

### 3. Android 兼容性
- 避免使用 Unicode 正则表达式（`\p{L}`, `\p{N}`）
- 避免使用 highlight.js 的语言定义（包含 Unicode 正则）
- 使用 Babel 转译 marked 库

### 4. 性能优化
- 简单的代码块渲染（无语法高亮）比高亮快得多
- 移除 highlight.js 减小包体积
- 缓存和懒加载进一步提升性能
