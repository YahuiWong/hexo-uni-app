## 🎯 前置准备

### 1. 确保项目可以本地构建

```bash
# 安装依赖
pnpm install

# 构建微信小程序
pnpm run build:mp-weixin
```

构建成功后会在 `dist/build/mp-weixin` 目录生成小程序代码。

### 2. 确认微信小程序 AppID

打开 `src/manifest.json`，找到微信小程序配置：

```json
{
  "mp-weixin": {
    "appid": "wx1234567890abcdef"
  }
}
```

记下这个 `appid`，后续需要用到。

## 🔑 获取微信小程序密钥

### 步骤 1: 登录微信小程序后台

访问：https://mp.weixin.qq.com

### 步骤 2: 下载上传密钥

1. 进入「开发」→「开发管理」→「开发设置」
2. 找到「小程序代码上传」区域
3. 点击「生成」按钮，下载上传密钥文件 `private.*.key`

**⚠️ 重要提示**：
- 该密钥只能下载一次，请妥善保管
- 如果丢失需要重新生成（旧密钥会失效）
- 不要将密钥提交到 Git 仓库

### 步骤 3: 查看密钥内容

打开下载的 `private.*.key` 文件，内容类似：

```
-----BEGIN EC PRIVATE KEY-----
MHcCAQEEIBxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
xxxxxxxxxxxxxxxxxxxxxxxxxxxxxoGCCqGSM49AwEHoUQD
QgAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxQ==
-----END EC PRIVATE KEY-----
```

复制完整内容（包括 `BEGIN` 和 `END` 行）。

## 🔐 配置 GitHub Secrets

### 步骤 1: 进入 GitHub 仓库设置

1. 打开你的 GitHub 仓库
2. 点击「Settings」→「Secrets and variables」→「Actions」
3. 点击「New repository secret」

### 步骤 2: 添加 AppID

- **Name**: `WEIXIN_APPID`
- **Secret**: 粘贴你的小程序 AppID（例如：`wx1234567890abcdef`）
- 点击「Add secret」

### 步骤 3: 添加私钥

- **Name**: `WEIXIN_PRIVATE_KEY`
- **Secret**: 粘贴完整的私钥内容（包括 `BEGIN` 和 `END` 行）
- 点击「Add secret」

**配置完成后应该有两个 Secrets**：
- `WEIXIN_APPID`
- `WEIXIN_PRIVATE_KEY`

## 🚀 触发自动部署

### 方式 1: 推送代码触发（自动）

当你推送代码到 `main` 分支时，如果修改了以下文件，会自动触发部署：
- `src/**` 目录下的文件
- `package.json`
- `pnpm-lock.yaml`

```bash
git add .
git commit -m "feat: 新功能"
git push origin main
```

### 方式 2: 手动触发

1. 进入 GitHub 仓库页面
2. 点击「Actions」标签页
3. 选择「微信小程序 CI/CD」workflow
4. 点击「Run workflow」按钮
5. 填写版本信息：
   - **版本号**: 例如 `1.0.1`
   - **版本描述**: 例如 `修复登录问题`
6. 点击「Run workflow」开始部署

### 查看部署状态

1. 在「Actions」页面可以看到工作流执行状态
2. 点击具体的运行记录可以查看详细日志
3. 绿色 ✅ 表示成功，红色 ❌ 表示失败

## 📱 提交审核

自动上传成功后，需要在微信小程序后台提交审核：

1. 登录 https://mp.weixin.qq.com
2. 进入「版本管理」页面
3. 在「开发版本」中找到刚上传的版本
4. 点击「提交审核」
5. 填写审核信息并提交

## 🛠️ 工作流程说明

### 完整流程

```
代码推送到 GitHub
    ↓
触发 GitHub Actions
    ↓
1. 检出代码
2. 安装 Node.js 和 pnpm
3. 安装项目依赖
4. 构建微信小程序
5. 上传到微信平台
    ↓
上传成功
    ↓
登录微信后台提交审核
```

### 构建步骤详解

1. **检出代码**: 从 GitHub 拉取最新代码
2. **设置环境**: 安装 Node.js 18 和 pnpm
3. **缓存依赖**: 缓存 pnpm 依赖以加快构建速度
4. **安装依赖**: 运行 `pnpm install`
5. **安装 CI 工具**: 安装 `miniprogram-ci`
6. **构建项目**: 运行 `pnpm run build:mp-weixin`
7. **创建密钥文件**: 从 Secrets 创建临时密钥文件
8. **上传代码**: 使用 `miniprogram-ci` 上传到微信平台
9. **清理密钥**: 删除临时密钥文件

## ❓ 常见问题

### 1. 上传失败：privatekey error

**原因**: 私钥配置错误

**解决方法**:
1. 检查是否正确配置了 `WEIXIN_PRIVATE_KEY`
2. 确保复制了完整的密钥内容（包括 BEGIN 和 END 行）
3. 重新生成密钥并更新 GitHub Secrets

### 2. 上传失败：appid error

**原因**: AppID 不匹配

**解决方法**:
1. 检查 GitHub Secrets 中的 `WEIXIN_APPID` 是否正确
2. 检查 `src/manifest.json` 中的 `mp-weixin.appid` 是否正确
3. 确保两者完全一致

### 3. 构建失败：找不到模块

**原因**: 依赖安装失败

**解决方法**:
```bash
# 本地测试构建
pnpm install
pnpm run build:mp-weixin

# 如果本地构建成功，检查 pnpm-lock.yaml 是否提交到 Git
git add pnpm-lock.yaml
git commit -m "chore: 更新依赖锁文件"
git push
```

### 4. 如何查看详细日志？

1. 进入 GitHub 仓库「Actions」页面
2. 点击失败的工作流
3. 点击具体的步骤查看日志
4. 复制错误信息进行排查

### 5. 如何修改版本号？

**手动触发时**：在「Run workflow」对话框中填写版本号

**自动触发时**：默认版本号为 `1.0.0`，可以修改 `.github/workflows/deploy-weixin.yml` 文件：

```yaml
env:
  VERSION: ${{ github.event.inputs.version || '1.0.1' }}  # 修改这里
```

### 6. 如何修改编译设置？

编辑 `scripts/upload-weixin.js` 文件，修改 `setting` 对象：

```javascript
setting: {
  es6: true,              // ES6 转 ES5
  es7: true,              // 增强编译
  minify: true,           // 压缩代码
  minifyJS: true,         // 压缩 JS
  minifyWXML: true,       // 压缩 WXML
  minifyWXSS: true,       // 压缩 WXSS
  codeProtect: false,     // 代码保护（需开通）
  autoPrefixWXSS: true,   // 自动补全 WXSS
}
```

## 📊 最佳实践

### 1. 版本号规范

建议使用语义化版本号（SemVer）：

- **主版本号** (Major): 不兼容的 API 修改 `1.0.0` → `2.0.0`
- **次版本号** (Minor): 向下兼容的功能新增 `1.0.0` → `1.1.0`
- **修订号** (Patch): 向下兼容的问题修正 `1.0.0` → `1.0.1`

### 2. 版本描述规范

版本描述应简洁明了，说明本次更新的主要内容：

```
✅ 好的描述：
- "修复登录失败问题"
- "新增文章收藏功能"
- "优化首页加载性能"

❌ 不好的描述：
- "更新"
- "修复 bug"
- "优化"
```

### 3. 分支策略

建议采用以下分支策略：

- `main`: 生产环境分支，触发自动部署
- `develop`: 开发分支，用于日常开发
- `feature/*`: 功能分支

```bash
# 开发新功能
git checkout -b feature/comment
# ... 开发 ...
git commit -m "feat: 添加评论功能"

# 合并到 develop 测试
git checkout develop
git merge feature/comment

# 测试通过后合并到 main 触发部署
git checkout main
git merge develop
git push origin main
```

### 4. 提交信息规范

使用约定式提交（Conventional Commits）：

```
feat: 新功能
fix: 修复问题
docs: 文档更新
style: 代码格式
refactor: 重构
test: 测试相关
chore: 构建/工具相关
```

## 📝 附录

### 本地测试上传脚本

如果想在本地测试上传功能（私钥以环境变量传入，不落盘）：

```bash
# 1. 安装 miniprogram-ci
pnpm add -D miniprogram-ci

# 2. 构建项目
pnpm run build:mp-weixin

# 3. 设置环境变量并运行上传脚本（WEIXIN_PRIVATE_KEY 为完整 PEM 私钥字符串）
APPID=你的AppID \
WEIXIN_PRIVATE_KEY="$(cat /path/to/your/private.key)" \
VERSION=1.0.0 DESCRIPTION="测试上传" node scripts/upload-weixin.js
```

**⚠️ 注意**: 私钥通过 `WEIXIN_PRIVATE_KEY` 环境变量传入，请勿将其写入仓库或提交到版本控制。本地私钥文件请妥善保管（建议放在仓库目录之外）。
